# 04 · 前端工程结构与配置

> 技术栈：Vue 3.5 + TypeScript + Vite 6 + Pinia + Vue Router 4 + Element Plus + pnpm workspace（monorepo）
> 核心命题：**一个门户 + 多个业务应用 + 一个超管后台**，共享同一套权限 SDK。

---

## 一、为什么用 monorepo

需求里"农户可以同时用商贩交易和农资交易两个应用，商贩只用商贩交易"意味着：

- 多个前端应用共享**同一套登录态、租户切换、权限校验逻辑**；
- 若各应用各自实现，权限口径必然漂移，前后端对不上；
- 因此把权限能力抽成 `@agri/auth` 包，各应用只写业务页面。

```
门户登录 → 选择租户 → 选择应用 → 加载该应用的前端资源 + 该成员在该应用下的权限码 → 渲染菜单/按钮
```

## 四、权限核心实现

### 4.1 权限 Store

```ts
// packages/auth/src/stores/usePermissionStore.ts
import { defineStore } from 'pinia'
import type { PermissionNode, DataScopeRule } from '@agri/shared'

interface PermissionState {
  /** 当前成员在当前应用下拥有的全部权限码（后端下发的扁平集合） */
  codes: Set<string>
  /** 菜单树（后端按权限过滤后的结果，前端不再二次过滤，避免口径不一致） */
  menus: PermissionNode[]
  /** 数据范围：objectCode -> 规则，用于页面提示与查询参数预置 */
  scopes: Record<string, DataScopeRule>
  loaded: boolean
}

export const usePermissionStore = defineStore('permission', {
  state: (): PermissionState => ({
    codes: new Set(),
    menus: [],
    scopes: {},
    loaded: false,
  }),

  getters: {
    /**
     * 权限校验唯一入口。
     * 注意：这里只是【体验优化】，真正的拦截永远在后端。
     */
    has: (state) => (code: string | string[]): boolean => {
      if (state.isSuper) return true
      const list = Array.isArray(code) ? code : [code]
      // 支持 | 分隔的"或"语义：'trade:order:edit|trade:order:admin'
      return list.some((c) =>
        c.split('|').some((item) => state.codes.has(item.trim())),
      )
    },

    scopeOf: (state) => (objectCode: string): DataScopeRule | undefined =>
      state.scopes[objectCode],
  },

  actions: {
    async load(appId: number, memberId: number) {
      const data = await authApi.fetchMyPermissions({ appId, memberId })
      this.codes = new Set(data.codes)
      this.menus = data.menus
      this.scopes = data.scopes
      this.loaded = true
    },

    reset() {
      this.codes.clear()
      this.menus = []
      this.scopes = {}
      this.loaded = false
    },
  },
})
```

### 4.2 动态路由（菜单 → 路由）

```ts
// packages/auth/src/router/buildRoutes.ts
import type { RouteRecordRaw } from 'vue-router'
import type { PermissionNode } from '@agri/shared'

/**
 * 关键约定：
 *  1. 菜单树由【后端】按权限过滤后下发，前端不做二次权限过滤 —— 单一口径，避免前后端打架；
 *  2. 组件通过路径映射懒加载，映射表由各应用在 permission-config.ts 中声明；
 *  3. 未在映射表中的菜单降级为 404 占位，不要让整个路由构建崩掉。
 */
export function buildRoutes(
  menus: PermissionNode[],
  componentMap: Record<string, () => Promise<unknown>>,
  layout: RouteComponent,
): RouteRecordRaw[] {
  const toRoute = (node: PermissionNode): RouteRecordRaw => {
    const component = componentMap[node.componentPath ?? '']
    return {
      path: node.routePath,
      name: node.code,
      component: component ?? (() => import('@agri/auth/src/views/NotImplemented.vue')),
      meta: {
        title: node.name,
        icon: node.icon,
        permissionCode: node.code,
        keepAlive: node.keepAlive ?? false,
      },
      children: node.children?.filter((c) => c.type === 'MENU').map(toRoute) ?? [],
    }
  }

  return [
    {
      path: '/',
      component: layout,
      redirect: menus[0]?.routePath ?? '/403',
      children: menus.filter((m) => m.type === 'MENU').map(toRoute),
    },
  ]
}
```

### 4.3 `v-permission` 指令

```ts
// packages/auth/src/directives/permission.ts
import type { Directive, DirectiveBinding } from 'vue'
import { usePermissionStore } from '../stores/usePermissionStore'

type Binding = string | string[]

/**
 * 用法：
 *   <el-button v-permission="PERM.ORDER_CREATE">发起交易</el-button>
 *   <el-button v-permission="[PERM.A, PERM.B]">批量操作</el-button>   // 任一满足即显示
 *   <el-button v-permission.disable="PERM.ORDER_EXPORT">导出</el-button>  // 置灰而非隐藏
 *
 * 再一次强调：这只是交互体验优化。
 * 后端 PermissionWebFilter 对每个 API 都会独立校验，前端绕过也无法越权。
 */
function resolve(el: HTMLElement, binding: DirectiveBinding<Binding>) {
  const store = usePermissionStore()
  const allowed = store.has(binding.value)

  if (binding.modifiers.disable) {
    el.classList.toggle('is-disabled', !allowed)
    // 用 pointer-events + aria 阻断，保留元素占位（避免表单抖动）
    el.style.pointerEvents = allowed ? '' : 'none'
    el.setAttribute('aria-disabled', String(!allowed))
    if (!allowed) el.setAttribute('title', '无操作权限')
  } else if (!allowed) {
    el.parentNode?.removeChild(el)
  }
}

export const permission: Directive<HTMLElement, Binding> = {
  mounted: resolve,
  updated: resolve,   // 切换租户后权限变化，必须重新求值
}
```

### 4.4 路由守卫

```ts
// packages/auth/src/router/guard.ts
import type { Router } from 'vue-router'
import { useAuthStore } from '../stores/useAuthStore'
import { useTenantStore } from '../stores/useTenantStore'
import { usePermissionStore } from '../stores/usePermissionStore'

export function setupGuard(router: Router, appCode: string) {
  router.beforeEach(async (to) => {
    const auth = useAuthStore()
    const tenant = useTenantStore()
    const perm = usePermissionStore()

    // 1. 未登录 → 回门户
    if (!auth.isLogin) {
      window.location.href = `${import.meta.env.VITE_PORTAL_URL}/login?redirect=${to.fullPath}`
      return false
    }

    // 2. 已登录但未选定租户/应用 → 回门户的身份选择页
    if (!tenant.ready) {
      window.location.href = `${import.meta.env.VITE_PORTAL_URL}/select-tenant`
      return false
    }

    // 3. 当前应用的 code 与进入的应用不匹配（用户从菜单点进了无权应用）→ 拒绝
    if (tenant.currentAppCode !== appCode) {
      return { name: 'Forbidden' }
    }

    // 4. 首次进入或切换租户后，加载权限
    if (!perm.loaded) {
      await perm.load(tenant.appId, tenant.memberId)
      // 权限加载后重新导航，确保动态路由已注册
      return to.fullPath
    }

    // 5. 路由级权限校验（菜单由后端过滤，这里兜底防止手输 URL）
    const required = to.meta.permissionCode as string | undefined
    if (required && !perm.has(required)) {
      return { name: 'Forbidden' }
    }

    return true
  })
}
```

### 4.5 租户切换（核心交互）

```vue
<!-- packages/components/src/TenantSwitcher.vue -->
<script setup lang="ts">
import { computed, ref } from 'vue'
import { useAuthStore, useTenantStore } from '@agri/auth'
import type { TenantCard } from '@agri/shared'

const auth = useAuthStore()
const tenant = useTenantStore()

/** 登录时后端下发的身份卡片：[{tenantId, tenantName, tenantType, apps:[...]}] */
const cards = ref<TenantCard[]>(auth.tenantCards)

const grouped = computed(() =>
  cards.value.map((c) => ({
    ...c,
    apps: c.apps ?? [],
  })),
)

async function switchTo(card: TenantCard, appId: number) {
  await tenant.switchTo({ tenantId: card.tenantId, appId })
  // 切换后必须整页刷新：路由表、菜单、权限、数据范围全部要重建，
  // 用 SPA 内跳转极易残留上一个租户的状态。
  window.location.href = appEntranceUrl(appId)
}

function appEntranceUrl(appId: number) {
  const app = cards.value.flatMap((c) => c.apps ?? []).find((a) => a.appId === appId)
  return app?.entryUrl ?? '/'
}
</script>

<template>
  <el-dropdown @command="({ card, appId }) => switchTo(card, appId)">
    <span class="tenant-switcher">
      {{ tenant.tenantName }} · {{ tenant.appName }}
      <el-icon><ArrowDown /></el-icon>
    </span>

    <template #dropdown>
      <el-dropdown-menu>
        <div v-for="card in grouped" :key="card.tenantId">
          <div class="group-title">
            {{ card.tenantName }}
            <el-tag size="small">{{ tenantTypeLabel(card.tenantType) }}</el-tag>
          </div>
          <el-dropdown-item
            v-for="app in card.apps"
            :key="app.appId"
            :command="{ card, appId: app.appId }"
            :disabled="app.appId === tenant.appId"
          >
            {{ app.appName }}
          </el-dropdown-item>
        </div>
      </el-dropdown-menu>
    </template>
  </el-dropdown>
</template>
```

> **切换租户必须整页刷新**。这是多租户前端最容易踩的坑：SPA 内存里残留着上一个租户的 Store、路由、缓存，轻则数据显示错乱，重则上一个租户的数据被带到新租户的表单里提交。宁可牺牲一次刷新体验。

### 4.6 API 层

```ts
// packages/shared/src/utils/request.ts
import axios from 'axios'
import type { AxiosInstance } from 'axios'

const request: AxiosInstance = axios.create({
  baseURL: import.meta.env.VITE_API_BASE,
  timeout: 15000,
})

request.interceptors.request.use((config) => {
  const token = localStorage.getItem('AGRI_TOKEN')
  if (token) config.headers.Authorization = `Bearer ${token}`
  // 注意：租户/成员信息一律从 token 中解析，前端不自己传 X-Tenant-Id。
  // 网关会剥离外部传入的内部头，防止伪造租户越权。
  return config
})

request.interceptors.response.use(
  (res) => res.data,
  (error) => {
    const code = error.response?.status
    if (code === 401) {
      // 令牌失效 → 回门户重新登录（不要静默刷新后带着旧租户上下文继续）
      localStorage.removeItem('AGRI_TOKEN')
      window.location.href = `${import.meta.env.VITE_PORTAL_URL}/login`
    }
    if (code === 403) {
      ElMessage.error(error.response?.data?.message ?? '无操作权限')
    }
    return Promise.reject(error)
  },
)

export default request
```

## 五、三种用户类型的界面差异（落地到需求）

| 用户 | 登录后的身份卡片 | 可见应用 | 说明 |
|---|---|---|---|
| 农户（王家村） | 1 张：王家村（VILLAGE） | 商贩交易 + 农资交易 | `tenant_type_app` 中 VILLAGE 关联两个应用 |
| 商贩（城东农贸市场） | 1 张：城东农贸市场（MARKET） | 商贩交易 | MARKET 只关联 TRADE |
| 农资商贩（某化肥厂） | 1 张：某化肥厂（AGENT） | 农资交易 | AGENT 只关联 AGRO_INPUT |
| 双重身份用户 | 2 张：王家村 + 城东农贸市场 | 按各租户类型分别计算 | 切换 = 切 member，权限与数据范围全换 |
| 超级管理员 | 特殊：不显示租户卡片 | 系统管理后台 | 走 `admin-web`，`user_kind=SUPER_ADMIN` |

**数据权限在前端的体现**：
- `DataScopeTag.vue` 展示当前数据范围（如"仅看本村民小组"），让用户明白为什么只看到部分数据 —— 这是多租户系统必备的可用性设计，否则用户会认为"系统丢了数据"；
- `OrgTreeSelect.vue` 的组织树由后端按数据范围过滤后返回，前端不做过滤。

## 六、开发规范

1. **权限码集中声明**：一律在 `permission-config.ts` 中定义为常量，禁止在模板里硬编码字符串；
2. **菜单口径唯一**：菜单树由后端下发，前端不自行根据权限码过滤（避免两侧规则不一致）；
3. **切换租户即刷新**：禁止在 SPA 内平滑切换租户上下文；
4. **不信任前端**：所有 `v-permission` 只是体验优化，后端 `PermissionWebFilter` 才是真正的拦截；
5. **数据范围不写死**：页面查询条件里的组织/人员筛选，其可选项由后端按数据范围返回，前端不假设"能看到全部组织"。
